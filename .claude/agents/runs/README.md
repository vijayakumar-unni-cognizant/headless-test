# ADLC Run History

Working directory for the **AEM Program Agent** and the 9 ADLC specialists. Every orchestrated ADLC run lands here as a self-contained `{run-id}/` subdirectory. The authoritative layout is in [`../ADLC-SPEC.md`](../ADLC-SPEC.md) §9.3; this README mirrors that contract for quick reference.

## Layout

```

├── README.md                          # this file (tracked)
└── {run-id}/                          # one folder per orchestrated run (gitignored)
    ├── PLAN.md                        # phase plan + work breakdown (Program Agent, step 3)
    ├── DECISIONS.md                   # irreversible calls — pattern choices, reuse-vs-new,
    │                                  # promotion approvals, human checkpoints

    │
    ├── plan/                          # strategist outputs (Plan stage)
    │   ├── requirements.yaml
```

### Run-id format

`{ISO-timestamp-Z}-{kebab-case-slug}` — e.g. `2026-07-02T-az-home-page`, `2026-06-29T18-09Z-cs-teaser`. Generated by the Program Agent at step 2 of its workflow. The timestamp lets concurrent runs coexist without collision; the slug makes the directory grep-able.

## Which agent writes where

| Stage | Agent | Writes into |
|---|---|---|
| Plan | `strategist` | `plan/`, `handoffs/strategist.yaml` |
| Design | `designforge` | `design/` (markdown only), `handoffs/designforge.yaml` |
| Implement — code | `blockwright` | Repo (`core/`, `ui.apps/`, `ui.frontend/`, `ui.content/.../conf/`) + `implement/blockwright/`, `handoffs/blockwright.yaml` |
| Implement — config | `configsmith` | Repo (`ui.config/`, `dispatcher/src/`, `cdn.yaml`) + `implement/configsmith/`, `handoffs/configsmith.yaml` |
| Integrate — external | `bridgesmith` | Repo (`core/.../servlets`, `core/.../events`) + `integrate/bridgesmith/`, `handoffs/bridgesmith.yaml` |
| Integrate — content | `composer` | Repo (`ui.content/`, CF models, persisted queries) + `integrate/composer/`, `handoffs/composer.yaml` |
| Test — quality + build | `auditron` | `test/auditron/`, `handoffs/auditron.yaml` |
| Release — raise PR | `pilot` | `deploy/pr-request.md`, `deploy/pr-body.md`, `handoffs/pilot.yaml` (`status: awaiting_lead_approval`). Auto-runs once Auditron passes; the flow then **pauses** for the Lead's manual merge + real-env deploy. Optional RDE sandbox → `deploy/deploy-rde.md`. |
| Test — NFR + UI — **LAST stage** | `sentinel` | `test/sentinel/`, new Playwright specs under `ui.tests/test-module/tests/`, `handoffs/sentinel.yaml`. Runs on resume against the **real environment URL** the human supplies (not a local SDK). Terminal acceptance verdict. |
| Orchestration | `aem-program-agent` | `PLAN.md`, `DECISIONS.md`, `dispatch/*.md`, `reports/*` |

Independent-mode runs (a specialist invoked directly without the Program Agent) write to the same paths — the layout is mode-invariant per ADLC-SPEC §6.3.

## Why this directory is gitignored

Run history is transient. Most runs produce lasting artifacts directly in the repo (components, configs, tests, deployments); the per-run PLAN / dispatch / handoff / reports are orchestration scaffolding, not enduring documentation. Committing every run would create noise without value, and `tokens.json` changes every session.

The directory itself stays tracked (via this README) so agents can write into a known-good path without first creating it.

## When to commit a specific run

Useful exceptions:

- **Pilot / adoption runs.** During ADLC roll-out, keeping the first few runs lets the team learn from real handoff shapes and Sentinel reports.
- **Audit-relevant runs.** Anything that materially changed production (a migration, a security baseline change, an eventual out-of-ADLC Prod promotion driven from this run's artifacts) is worth keeping for change history.
- **Note:** postmortems and incident forensics are no longer ADLC outputs — those live outside `runs/` in the external SRE / on-call process.
- **Sentinel gate reports.** Occasionally worth committing `test/sentinel/*.html` when the numbers are the evidence a stakeholder needs to see.

To commit a run despite the gitignore:

```bash
git add -f .claude/agents/runs/2026-07-02T-az-home-page/
git commit -m "Preserve AZ home page run for postmortem reference"
```

## Cleanup

Old runs are safe to delete locally — they exist only to support a recent or in-flight run's handoff chain. A practical cadence:

```bash
# Keep last 30 days of runs locally
find .claude/agents/runs -maxdepth 1 -type d -mtime +30 -not -name runs -exec rm -rf {} +
```

Adjust the window to your tolerance. If you commit selected runs (per §"When to commit a specific run"), those are outside the gitignore and will not be touched by this cleanup.
